# Отложенные пункты ревью (backlog)

Состояние на 2026-11-27, после исправления findings read-only ревью 23 модулей
(11 бэкенд + 12 фронтенд). Здесь собрано всё, что осознанно **не** сделано,
с точными адресами и планом продолжения. Документ самодостаточен: полные отчёты
лежали во временном каталоге (`/tmp/opencode/reviews/`), но для работы достаточно
этого файла и `docs/SESSION-STATE.md`.

## Как пользоваться

- Приоритет: сначала Important (раздел 1), затем частично закрытые (раздел 2),
  затем Minor (раздел 3). `[manual]`-пункты проверяет пользователь на устройствах.
- Один пакет работ = один агент, у агента эксклюзивный список файлов; параллельно
  не более 3 агентов. Правила — `AGENTS.md`.
- Каждому фиксу — тест. Проверки: `make lint`, `make test`, `make frontend:e2e`.
- Коммит/пуш — только по явной команде пользователя.

## 1. Important (требуют решения или кросс-модульного контракта)

### 1.1. Реакции и read-status в клиентском delta-sync

- Где: `backend/service/sync.go` (`SyncResponse`, `nextSyncCursor`),
  `frontend/src/sync/deltaApplier.ts`, `frontend/src/db/*Repo.ts`.
- Симптом: реакции и статусы прочтения не входят в дельту; офлайн-клиент
  сходится по ним только переоткрытием чата. Курсор висит на
  `messages.updated_at`, поэтому событие «изменилась только реакция» теряется.
- Почему отложено: меняет контракт Sync сразу для бэкенда и фронтенда
  (кросс-модульная фича), нельзя отдать одному агенту без пересечения файлов.
- План: добавить в дельту отдельные списки reaction/read-событий с монотонным
  курсором; применить их в `deltaApplier` до сообщений; тесты на сходимость
  «офлайн → онлайн» без перезагрузки чата.

### 1.2. Plaintext-имена E2EE-вложений

- Где: `backend/transport/files.go` (ответ с `OriginalName`),
  `backend/model/types.go` (`File.OriginalName`), SDK/фронтенд-загрузка.
- Симптом: сервер хранит и рассылает настоящее имя файла E2EE-вложения, хотя
  содержимое зашифровано. Метаданные утекают в дамп БД и федерацию.
- Почему отложено: продуктовое решение + изменение контракта загрузки
  (клиент/боты/SDK). Возможный трейд-офф: удобство списка файлов против
  метаданных.
- План: передавать имя внутри зашифрованного payload сообщения (или в
  зашифрованном заголовке файла), серверу оставить только `id`, размер и MIME
  (MIME тоже кандидат на шифрование). Согласовать с SDK.

### 1.3. Полная аутентификация ключевой директории получателя

- Где: `frontend/src/e2ee/keys.ts` (сейчас сделан TOFU-пиннинг ключа и
  предупреждение при смене).
- Симптом: злонамеренный сервер может подменить публичный ключ получателя —
  односторонний read-MITM. Пиннинг ловит смену, но не подмену при первом контакте.
- Почему отложено: требует смены протокола (подпись encryption-ключа ключом
  identity, transparency log или сверка отпечатков вручную).
- План: подписывать ключ шифрования ключом подписи identity и проверять цепочку;
  минимум — UI сверки отпечатков для параноидального режима.

### 1.4. Общая IDB-транзакция «строка сообщения + blobs + enqueue»

- Где: `frontend/src/hooks/useMessageSender.ts` (путь отправки),
  `frontend/src/db/{messagesRepo,outboxRepo,pendingBlobsRepo}.ts`.
- Симптом: падение процесса между `messagesRepo.upsert`, сохранением blobs и
  `outboxRepo.enqueue` оставляет сообщение навсегда в статусе «отправляется»;
  автоматического recovery нет.
- Почему отложено: риск для основного пути отправки; нужен отдельный
  рефакторинг с транзакцией по трём сторам и восстановлением при старте.
- План: одна IDB-транзакция на все три записи; при старте — скан «queued без
  op» и «op без строки» с компенсацией; тесты на краш между шагами.

## 2. Частично закрытые пункты

- **Память больших вложений** (`useDecryptedFileUrl`): есть лимит 256 MiB и
  отмена при unmount, но нет потоковой/worker-расшифровки — файл целиком лежит
  в памяти. Продолжение: chunked-расшифровка или Web Worker, лимит по
  `navigator.deviceMemory`.
- **MSE** (`useMediaUrl`): проверяются `resp.ok`/`206`/`Content-Range`, но файл
  докачивается целиком; нет окна буфера и паузы загрузки. Продолжение:
  управление `sourceBuffer.buffered` и отмена лишних запросов.
- **Звонки**: C6 закрыт polling-ом 5 с + локальным таймаутом 60 с, но нет
  прямой подписки на `connected`/`sse_closed` из SSE-слоя. Продолжение:
  экспортировать события из `useSse.ts`/`useSseEvents.ts` и вызывать reconcile
  напрямую (это уберёт задержку до 5 с).
- **Локальный замок**: 6-значный PIN усилен blocklist/троттлингом/потолком
  PBKDF2, но остаётся слабым к офлайн-перебору. Продолжение: продуктовое
  решение — более длинная фраза-пароль или обязательный passkey.
- **Восстановление после recovery**: recovery теперь явно предупреждает и
  снимает лок с подтверждением, но не восстанавливает прежний PIN автоматически.
  Продолжение: предложить повторную установку лока сразу после recovery.

## 3. Minor по зонам

### Frontend: медиа и звонки
- Кнопка «Повторить» у ошибок медиа (нужен retry-контракт в хуках + ключи локалей).
- `aria-label` стрелок `ImageLightbox` на языке интерфейса (нет ключей
  `previous`/`next` в локалях).
- Аудио-режим звонка (`video: false` по кнопке) — требует UI в `ChatPage` и
  решения по умолчанию.
- `sessionStorage`-ключи `fastchat.call*` не привязаны к аккаунту (ломает
  текущий reload-протокол при переносе).

### Frontend: auth/SSE
- UI-индикация терминального `sse_limit` (сейчас просто останавливается SSE).
- Глобальный таймаут `request()` (сейчас таймауты точечные).
- Push-превью при локальном замке (SW показывает текст до разблокировки).
- Модель угроз для токенов в `localStorage` — задокументировать, не переделывать
  без решения.
- Мёртвый `component` у маршрута `/chat/$chatRef`.

### Frontend: группы, админка, прочее
- Пагинация `AuditTab` (нужен `adminListAudit` с offset/limit в `api.ts`).
- Клавиатурный доступ к удалению чата в `ChatList` (сейчас только контекстное
  меню; кнопку «⋯» убирали осознанно — нужно решение).
- Локализация ошибок `api.ts` (`errorText`) вместо сырых `http 400: ...`.
- Полный рефакторинг `useAdminList` (осталось дублирование UsersTab/ChatsTab).

### Frontend: чат/sync
- `lastSyncedId` рядом с курсором в IDB (keyset-пагинация `(updated_at, id)`).
- Отдельный статус для failed-edit (сейчас сообщение помечается `failed` и
  серверные апдейты по нему пропускаются).
- Тесты на восстановление черновика при отмене edit и на гонку пагинации тредов
  (нет harness для `useChatPage`).
- `db/init.ts`: orphan-соединение, если `blocked()` победил (закрывать
  `opened` в catch).
- `deltaApplier`/`chatsRepo`: один проход по чатам в транзакции вместо
  `getAll("chats")` + notify-шторма на каждый тик; `updateMemberStatus` читает
  вне транзакции.

### Backend
- `go mod tidy`: `gopkg.in/gomail.v2` больше не импортируется после переписывания
  SMTP-сендера — убрать из `go.mod`/`go.sum`.
- `transport/transport.go`: `checkSSEHeartbeat` детектит истечение только по
  `Authorized`; hub-часть исправлена, но heartbeat-«зомби» в transport остался.
- Per-email троттлинг `send-code` (инбокс-бомбинг).
- `trusted_proxies` для ключевания лимита `sse-auth`.
- Мёртвые обёртки, которые держат чужие тесты: `AddRawMessage`,
  `GetMessagesPaginated`, `GetThreadMessagesPaginated`, `CreateUser`,
  `GetUserByToken`, `Service.SendMessage`, `TestValidCoords` — удалять вместе с
  тестами.
- `X-Request-ID` из заголовка клиента — осознанный трейд-офф, только
  документировать.

## 4. [manual] — проверка на реальных устройствах

- iOS Safari: long-press меню сообщения (контекстное меню не приходит).
- Safari: autoplay рингтона и `play()` удалённого аудио.
- Android: WebAuthn PRF во встроенном менеджере паролей (Google Password
  Manager), ручная блокировка, passkey-бэкап.
- Мобильный layout: `fullScreen` модалок, safe-area в `EndedCallNotice`.
