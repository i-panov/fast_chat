## Текущая сессия: v3 E2EE (не закоммичено)

Цель: один мастер-ключ аккаунта (X25519 + Ed25519), парольный/passkey-бэкап,
локальный PIN/passkey lock, ручная ротация, только payload v3.

Сделано:

- v3-шифрование/расшифровка, конверт на участника с `keyVersion`, AAD-привязка.
- Бэкап v4: пароль + WebAuthn PRF; passkey-восстановление персистит ключи и историю.
- Обязательный бэкап-гейт: блокирует только подтверждённое отсутствие (`none`);
  `unknown` (офлайн/5xx) не запирает, после ошибки сохранения есть аварийный выход.
- PIN/passkey: история ключей и identity-цепочка входят в локальный бэкап и не
  лежат в plaintext; «забыл PIN» с подтверждением и проверкой восстановления.
- Ротация encryption/signing: версия, история, подписанная цепочка, бэкап до
  публикации; запрещена при локальном lock и passkey-обёртке серверного бэкапа.
- Сервер: монотонная `masterKeyVersion` и версия бэкапа (409 на откат и на
  запись бэкапа отставшим устройством), боты не меняют identity повторным
  `enableE2EE`; федерация требует protocol v2 (v1 — явный отказ).
- «Начать заново» публикует замену на `serverVersion + 1`; ротация сверяет
  серверный ключ, публикует его до записи бэкапа и не глотает ошибку.
- Локальный lock: identity не создаётся при закрытом локе, расшифрованные
  вложения и текстовый кэш чистятся при блокировке, «забыл PIN» с проверкой
  восстановления.
- Автолок вынесен в корневой layout; legacy per-device restore/revoke удалены.
- Запись ключей привязана к захваченному аккаунту (`setNoNotifyFor`), ротации
  сериализованы Web Lock; удаление бэкапа атомарно по версии; восстановление
  сверяет pubkey/версию с сервером.
- SDK: Python `identity_key`, TS `keyVersion`; `botID` подгружается лениво;
  signing-ключи TS/Python совместимы (32-байтовый seed).
- Recovery/бэкап: stale-ошибки ведут в восстановление; recovery при локальном
  локе не запирает окно; удаление бэкапа атомарно по версии.
- Bot API: зашифрованная отправка требует клиентский `id`, чужая коллизия id
  не выдаётся за успех; федеративный прокси принимает пустую identity.
- Локальный lock: расшифровка вложений/текста не дописывает plaintext после
  закрытия; аудио и локальный поиск очищаются по событию лока.
- Документация: README (v3, API, федерация), SDK README (breaking changes),
  исторические спеки помечены как superseded.
- Регрессионные тесты: `frontend/src/e2ee/rotation.test.ts`, pinning/AAD в
  `e2ee.test.ts`, монотонность версии, backup-версия и федеративный протокол.

Осталось:

- Ручной деплой и проверка на реальных устройствах/браузерах — за пользователем.
- Дропнуть старую серверную БД и IndexedDB клиентов: формат v3 несовместим.

    Исправлено: `connect-src 'self' blob: …`, `media-src 'self' blob:`;
    тест CSP в `backend/main_test.go` проверяет оба директивы.
29. Плейнтекст-видео (серверный бот) зависало на лоадере после перезагрузки:

## Грабли, на которые уже наступали

- **Read-only режим.** Правка `AGENTS.md`/файлов отклоняется — сначала переключить
  permission preset на `workspace-write`, иначе агент тратит ход на объяснение.
- **Субагенты.** Не слать им сообщения и не прерывать, пока они работают; дождаться
  отчёта, затем самому проверить замечания.
- **Линтеры.** Частые падения: `varnamelen`, unused variables, duplicate strings,
  `react-hooks/set-state-in-effect` (последний — задокументированное исключение).
- **Финальные проверки.** `make lint` / `make test` по этапам, а не «final» один раз
  в конце: зелёные тесты — не повод заканчивать ход (см. «Границы хода» в `AGENTS.md`).
- **Goal-лимит.** Цель с `maxGoalRounds: 10` на 14 пунктов упирается в `round-limit`
  и блокируется. Лимит ставить с запасом: примерно 2 раунда на пункт.
